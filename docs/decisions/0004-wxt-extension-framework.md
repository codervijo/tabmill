## Context

Extensions need MV3 builds for five surfaces (popup, side panel, devtools, context menu,
content scripts on Google Maps), a manifest generated from extension.yaml, hot reload, and
zip packaging, with minimal dependencies. Compared in v1.A (NOTES.md § Spike 1): WXT, Plasmo,
crxjs + Vite, plain Vite.

## Decision

Use **WXT 0.21.x** (minor pinned) for every extension, run only inside the builder docker
(ADR-0003). `wxt.config.ts` reads the manifest JSON generated by the Python CLI (ADR-0002);
the CLI also writes `version` into the extension's `package.json` (WXT names the zip from it).
Operator decision, 2026-10-03.

## Consequences

**Good:** all five surfaces supported; function-valued manifest; per-part hot reload;
built-in `wxt zip`; actively maintained; v1.A test build showed no dev-only permission or
reload code in the prod output.
**Bad:** ~176 dev-only lockfile entries; pre-1.0 (breaking minors possible — pin and read
release notes on bumps); content/background runtime code must live inside `main()`.
The v1.A build checks ran outside docker and must be re-verified in the builder (v1.B).

## Alternatives considered

- **crxjs 3 + Vite** — lighter (91 entries) but zip, dev wiring, and entrypoint conventions
  would be ours to build. Fallback if WXT gets in the way.
- **Plasmo** — unmaintained since 2025-05, Parcel-based, 646 entries. Rejected.
- **Plain Vite** — most custom code to own. Rejected.
