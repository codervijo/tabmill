## Context

All Node work runs in the central builder (ADR-0003), but the builder doesn't fit WXT
extensions out of the box: the React stack assumes a `webapp/` dir, `dev_container.sh` mounts
only `${PWD}` (so `../tabmill` is invisible for cross-repo package linking), and the Playwright
image is pinned to v1.46.0. The builder is a separate, shared repo.

## Decision

**Do not change the builder repo.** The workspace includes the builder Makefile and adapts it
with a `Makefile.local` (the builder's `-include Makefile.local`, included last, wins):
override `deps` / `build` / `dev` / `test` / `zip` targets for WXT, and set `VOLUME_MOUNT`
(read by `dev_container.sh`) to mount the common parent of TOOL_DIR and WORKSPACE_DIR.
`Makefile.local` is generated by `tabmill init` from a template in TOOL_DIR (tool code),
never hand-edited in the workspace. Operator decision, 2026-10-03.

## Consequences

**Good:** no changes to a repo the whole sites fleet depends on; Tabmill owns its build quirks.
**Bad:** overrides can drift from builder changes; the Playwright image version can't be
bumped this way unless `Makefile.local` points `DOCKERFILE_NAME`/`DOCKERFILE_PATH` at a
Tabmill-owned Dockerfile — decide in v1.B when smoke tests land.

## Alternatives considered

- **Add a WXT stack to the builder** — cleaner long-term, but touches shared infrastructure. Rejected for now.
