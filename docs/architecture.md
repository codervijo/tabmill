# Architecture — tabmill

How Tabmill is built. The "HOW" companion to `docs/prd.md`. v1.A: target shape, mostly
proposed — sections marked *(proposed)* depend on decisions not yet accepted.

## 1. Project layout

Two repos, related by a computed relative layout (ADR-0007):

```
~/work/projects/
├── builder/                         central builder (Makefiles, Dockerfiles)
├── droyfun/tabmill/                 TOOL_DIR
│   ├── Makefile + Makefile.local    tool build via builder Python stack (D-018)
│   ├── pyproject.toml  cli/tabmill/ Python CLI (ADR-0002)
│   ├── recipes/<slug>/              extension source: extension.yaml + feature code (ADR-0008)
│   ├── templates/extension/<tpl>/   generic surface code (popup today)
│   ├── templates/workspace/  ci/    rendered into the workspace by `tabmill init`
│   ├── skills/  packages/ (v1.E)  docs/
│   └── .claude/skills/tabmill-dev/
└── plugins/chrome-extension-projects/   WORKSPACE_DIR = $TABMILL_WORKSPACE
    ├── chrome-dejargon/ … (5 pre-tabmill projects — untouched)
    ├── .claude/skills/  CLAUDE.md   installed/generated by `skills sync` (sha manifest)
    ├── .github/workflows/extensions.yml
    ├── extensions/<slug>/           generated by tabmill — never hand-edited (ADR-0008)
    ├── Makefile + Makefile.local    builder react stack → WXT, docker only (ADR-0005)
    ├── pnpm-workspace.yaml          extensions/* + ../../droyfun/tabmill/packages/*
    ├── registry.json  TODO.md  package.json  .gitignore
    └── .tabmill-ref                 tabmill commit pinned for CI
```

## 2. Core mechanisms

- **YAML → manifest**: the Python CLI validates extension.yaml (pydantic schema) and writes a
  generated manifest JSON into the extension; `wxt.config.ts` (ADR-0004) only reads that file.
  The CLI also writes `version` into the extension's `package.json` (WXT names the zip from it).
- **Node boundary** (ADR-0003): the CLI runs Node work as `make <target>` in WORKSPACE_DIR,
  which forwards to the builder docker. Nothing Node runs on the host.
- **Linking** *(proposed)*: pnpm workspace spanning both repos; `@tabmill/*` as `workspace:*`
  symlinks; TS source consumed directly by Vite.
- **Two kinds of workspace files** (`cli/tabmill/workspace.py`):
  - *seed* (`templates/workspace/seed/`: `TODO.md`, `registry.json`, `package.json`, `.gitignore`) —
    workspace-owned; `init` creates them if missing and never touches them again.
  - *managed* (`templates/workspace/managed/` + `ci/` + `skills/`: `Makefile`, `Makefile.local`,
    `pnpm-workspace.yaml`, `CLAUDE.md`, `.github/workflows/extensions.yml`, `.claude/skills/**`) —
    tool code rendered with computed relative paths (`{{name}}` placeholders; `dot-*` → `.*`).
- **Sync** (`cli/tabmill/sync.py`, run by `init` and `skills sync`): writes managed files;
  `.tabmill-sync.json` (workspace root) records sha256 of each; a tracked file whose hash changed,
  or an untracked file in the way = hand edit → refuse unless `--force`; files dropped from
  source are removed. Template changes reach the workspace on the next sync.
- **Init**: seed files + `extensions/` + `.tabmill-ref` pin, then sync.
- **Templates** (v1.E): `_shared/` (wxt + web-ext config, tsconfig, vitest/playwright configs,
  `src/lib/{brand,inject,messaging}.ts`, `shell.css`, smoke fixtures, config unit test) overlaid
  first, then the surface (`popup/`, `side-panel/` = background `setPanelBehavior` + sidepanel
  page; generator adds `action` to the manifest), then the recipe (D-022). Template-required
  permissions (`sidePanel`) must be declared + justified in the recipe; `create` adds them.
- **Schema + lint** (v1.E): `schema.py` (pydantic, `extra="forbid"`) + friendly checks in
  `extension.validate`; `lint.py` rules with dev/release severity — schema, perm-broad-host,
  perm-unused (bundle token scan), fill-placeholder, cta-placeholder, mv3-no-eval,
  mv3-no-remote-script, not-built, portfolio-similarity (Jaccard on single_purpose).
- **try** (v1.F): `make in-docker-try` → container installs Chromium (container only), builds
  (or starts `wxt dev` with `--dev`), runs `_shared/scripts/try.mjs` = Playwright
  `launchPersistentContext` headed, `channel: chromium`, unpacked build loaded, profile
  `/root/.tabmill-try/<slug>` in the container; window on the host via the container's X11
  mounts (`/tmp/.X11-unix`, xauth). `DOCKER_TTY=-it` when interactive so Ctrl-C reaches it.
- **Store** (v1.G): `assets` → `make in-docker-assets` (build renders `public/icon/*.png` from
  `assets/icon.svg` first; then `scripts/assets.mjs store` → `.output/store/`); `listing.py`
  (draft + PNG-header size checks + keyword counts); `cws.py` (v2 upload/publish/fetchStatus,
  SA JWT via google-auth or OAuth refresh, error body → remedy, `transient` flag); `publish`
  gates: TTY, `store_id`, `lint --release`, version zip, confirm.
- **Credentials + preflight** (v1.H, D-025): `apikeys.py` — `tabmill.env` (gitignored, mode
  600, atomic tmp+rename, comments kept), known `CWS_*` keys, masked `list`, probes (SA key
  parse, token exchange, publisher fetchStatus on the first `store_id`); `cws.load_env` reads it
  (env vars win). `preflight.py` — checks workspace / builder / docker / container / x11 /
  credentials; `NEEDS` maps commands → checks, run by `_preflight()` before any work.
- **Release + hub** (v1.I): `release` chains make targets + listing + `lint --release` + zip,
  warns at the slot cap (`registry.slots` — used = store PUBLISHED, limit default 2), appends the
  HUMAN publish line, then `hub`. `hub.py` mirrors lamill.io's zod `extensionSchema` as pydantic
  `HubEntry`; entries need a real tool page (`landing_page_url`), else skipped; `store_url`
  null until a `store_id` exists (D-032); status `published` once the store says so, else
  `unlisted` — pages live + noindex, hidden from the hub index (D-035); zero entries → file untouched; writes only
  `<hub_repo>/src/content/extensions.json`, never commits. Lint `hub-urls`: listing has
  privacy + support URLs; `--release` probes both for HTTP 200.
- **maps-overlay template** (v1.J, D-031): background `action.onClicked` → inject
  `content-scripts/overlay.js` (shadow-root panel + `renderShell`, toggles); `tabmill:open-page`
  message → `tabs.create` for extension pages; `overlay-preview.html` renders the panel for
  store screenshots + smoke; `TEMPLATE_PERMISSIONS["maps-overlay"] = scripting`.
- **Landing** (v1.K, D-033): `landing.py` — URL = portfolio_site + `landing_path`
  (default first keyword), self-contained brief → `.output/store/landing-brief.md`; `--check`
  probes 200, rewrites only the recipe's `landing_page_url` line, runs lamill's
  `settings gsc submit-sitemap` (soft-fail).
- **Catalog** (`cli/tabmill/catalog.py`, v1.D): `list` rows = `recipes/*/` ∪ workspace
  registry — status `recipe` / `generated` / `built` (`.output/chrome-mv3/manifest.json`) /
  `orphan` (registered, no recipe) / `invalid` (YAML error); placeholders = any `‹FILL›` value
  (dotted path) + placeholder URLs (D-015). `create` renders `templates/recipe/extension.yaml.tmpl`;
  `new`/`build` refuse `‹FILL›` in name / summary / single_purpose. Workspace optional for both.
- **Generator** (`cli/tabmill/generate.py`, ADR-0008): for each slug in `registry.json`,
  managed files under `extensions/<slug>/` = `templates/extension/<template>/**` (`*.tmpl`
  rendered) + `recipes/<slug>/**` overlay (same path wins; `extension.yaml` excluded) +
  generated `manifest.gen.json`, `package.json` (base dev toolchain + YAML `dependencies`),
  `src/generated/config.ts` (name, single purpose, privacy line, UTM CTA + footer URLs),
  `README.md`. `tabmill new` registers the slug; `build` = validate + sync + `make in-docker-build`.
- **popup template**: WXT `srcDir: src`, `wxt.config.ts` passes `manifest.gen.json`; popup shell
  (`src/lib/brand.ts`) renders title, `src/feature/` mount (stub unless the recipe supplies it),
  privacy line, CTA, "Built by Lamill" mark + footer; typed `createMessenger` helper; Vitest
  config test; Playwright smoke (`channel: 'chromium'`, extension ID read from chrome://extensions
  because popup-only extensions have no service worker).
- **Docker bridge**: workspace `make in-docker-<target>` starts the builder container `tabmill-ext`
  (react image, common-parent mount, port 3000) and runs `make <target>` inside, then chowns
  what it created back to the host user (the container runs as root). Node targets refuse on the host.
- **Lint modes**: each policy rule has a dev severity and a release severity; `lint --release`
  (zip for release, release skill, tag CI) applies the release one. `cta-placeholder` = warn → error (D-015).
- **Release**: build → lint --release → smoke → zip → assets → listing → `HUMAN: publish` line. Publish
  (attended) = CWS API v2 upload + publish on an existing item.

## 3. Data shapes / schemas

- **extension.yaml** (kickoff field list; typed schema lands in v1.E): `name`, `slug`,
  `version`, `single_purpose`, `template`, `permissions[] {name, justification}`,
  `optional_permissions[]`, `portfolio_site`, `landing_page_url`, `target_keywords[]`,
  `cta_text`, `cta_url`, `utm_campaign`, `store_category`, `analytics` (default `false`),
  `theme` (optional). Policy spike suggests adding: `remote_code`, `privacy_policy_url`,
  `data_usage {categories, limited_use}` — decide in v1.E.
- **registry.json**: per slug — `version`, `store_id` (from dashboard "Add new item"),
  `status`, `review_state`, `metrics[] {date, report, value}` (from CSV import).
- **tabmill.config.json** (TOOL_DIR): `builder`, `tool_repo`, optional `workspace` fallback.
  Env `TABMILL_WORKSPACE` / `TABMILL_BUILDER` win; relative paths resolve against TOOL_DIR.

## 4. Modules

`cli/tabmill/`: `cli` (typer app), `config`, `constants`, `output` (✓ ↷ ✗), `templates`,
`skills` (skill sources), `sync` (manifest engine), `workspace` (seed + managed files),
`extension` (YAML load/validate/manifest fields), `generate` (template + recipe), `registry`,
`catalog` (list rows, starter recipes). Planned packages: brand, funnel, messaging, analytics, policy (extracted in v1.E/v1.H).

## 5. CLI / UX surface

`init`, `skills sync`, `new`, `build` (minimal) (v1.B) · `list`, `create` (v1.D) ·
`dev`, `test`, `zip`, `lint`, full `build` (v1.E) · `assets`, `listing`, `publish` (v1.G) ·
`landing`, `status` (v1.H). Output uses `✓ ↷ ✗`.

## 6. Integrations / external APIs

- **Chrome Web Store API v2** — `chromewebstore.googleapis.com`; service account (preferred)
  or OAuth refresh token; scope `.../auth/chromewebstore`. Cannot create items or change
  visibility. Details: `skills/tabmill-release/reference.md`.
- **lamill CLI** — `lamill settings gsc submit-sitemap --site <d>`; landing pages deploy by
  git push to the site repo. No IndexNow (D-016).
- **GitHub** — tabmill is private; workspace CI checks it out with `TABMILL_PAT` (ADR-0007).
- **Metrics** — dashboard CSV export only.

## 7. Stack baselines

- **CLI:** Python ≥ 3.11, uv; typer, rich, httpx, pydantic, pyyaml.
- **Extensions (docker only):** Node ≥ 22, pnpm (only), TypeScript ~5.9 strict, WXT 0.21.x
  (ADR-0004), Playwright with `channel: 'chromium'`.

## 9. Risks

- Portfolio/duplicate-functionality policy — the largest store risk (NOTES § Spike 5).
- Cross-root pnpm workspace is undocumented behaviour (D-006).
- WXT is pre-1.0 — pin minor.
- Make variable leakage: the tool Makefile exports container settings; generated Makefiles use `:=`
  so inherited values can't redirect the container (a v1.B bug: build ran in `tabmill-tool`).
- Builder fit: handled by workspace `Makefile.local` (ADR-0005) — can drift from builder changes; Playwright image (v1.46.0) bump needs a Tabmill-owned Dockerfile.
- New-publisher cap of two published extensions.
