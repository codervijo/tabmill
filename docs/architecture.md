# Architecture — tabmill

How Tabmill is built. The "HOW" companion to `docs/prd.md`. v1.A: target shape, mostly
proposed — sections marked *(proposed)* depend on decisions not yet accepted.

## 1. Project layout

Two repos, related by a computed relative layout (ADR-0007):

## 2. Core mechanisms

- **YAML → manifest**: the Python CLI validates extension.yaml (pydantic schema) and writes a
  generated manifest JSON into the extension; `wxt.config.ts` (ADR-0004) only reads that file.
  The CLI also writes `version` into the extension's `package.json` (WXT names the zip from it).
- **Node boundary** (ADR-0003): the CLI runs Node work as `make <target>` in WORKSPACE_DIR,
  which forwards to the builder docker. Nothing Node runs on the host.
- **Linking** *(proposed)*: pnpm workspace spanning both repos; `@tabmill/*` as `workspace:*`
  symlinks; TS source consumed directly by Vite.
- **Two kinds of workspace files** (`cli/tabmill/workspace.py`):
  - *seed* (`templates/workspace/seed/`: `TODO.md`, `registry.json`, `package.json`, `.gitignore`) —
    workspace-owned; `init` creates them if missing and never touches them again.
  - *managed* (`templates/workspace/managed/` + `ci/` + `skills/`: `Makefile`, `Makefile.local`,
    `pnpm-workspace.yaml`, `CLAUDE.md`, `.github/workflows/extensions.yml`, `.claude/skills/**`) —
    tool code rendered with computed relative paths (`{{name}}` placeholders; `dot-*` → `.*`).
- **Sync** (`cli/tabmill/sync.py`, run by `init` and `skills sync`): writes managed files;
  `.tabmill-sync.json` (workspace root) records sha256 of each; a tracked file whose hash changed,
  or an untracked file in the way = hand edit → refuse unless `--force`; files dropped from
  source are removed. Template changes reach the workspace on the next sync.
- **Init**: seed files + `extensions/` + `.tabmill-ref` pin, then sync.
- **Templates** (v1.E): `_shared/` (wxt + web-ext config, tsconfig, vitest/playwright configs,
  `src/lib/{brand,inject,messaging}.ts`, `shell.css`, smoke fixtures, config unit test) overlaid
  first, then the surface (`popup/`, `side-panel/` = background `setPanelBehavior` + sidepanel
  page; generator adds `action` to the manifest), then the recipe (D-022). Template-required
  permissions (`sidePanel`) must be declared + justified in the recipe; `create` adds them.
- **Schema + lint** (v1.E): `schema.py` (pydantic, `extra="forbid"`) + friendly checks in
  `extension.validate`; `lint.py` rules with dev/release severity — schema, perm-broad-host,
  perm-unused (bundle token scan), fill-placeholder, cta-placeholder, mv3-no-eval,
  mv3-no-remote-script, not-built, portfolio-similarity (Jaccard on single_purpose).
- **try** (v1.F): `make in-docker-try` → container installs Chromium (container only), builds
  (or starts `wxt dev` with `--dev`), runs `_shared/scripts/try.mjs` = Playwright
  `launchPersistentContext` headed, `channel: chromium`, unpacked build loaded, profile
  `/root/.tabmill-try/<slug>` in the container; window on the host via the container's X11
  mounts (`/tmp/.X11-unix`, xauth). `DOCKER_TTY=-it` when interactive so Ctrl-C reaches it.
- **Store** (v1.G): `assets` → `make in-docker-assets` (build renders `public/icon/*.png` from
  `assets/icon.svg` first; then `scripts/assets.mjs store` → `.output/store/`); `listing.py`
  (draft + PNG-header size checks + keyword counts); `cws.py` (v2 upload/publish/fetchStatus,
  SA JWT via google-auth or OAuth refresh, error body → remedy, `transient` flag); `publish`
  gates: TTY, `store_id`, `lint --release`, version zip, confirm.
- **Credentials + preflight** (v1.H, D-025): `apikeys.py` — `tabmill.env` (gitignored, mode
  600, atomic tmp+rename, comments kept), known `CWS_*` keys, masked `list`, probes (SA key
  parse, token exchange, publisher fetchStatus on the first `store_id`); `cws.load_env` reads it
  (env vars win). `preflight.py` — checks workspace / builder / docker / container / x11 /
  credentials; `NEEDS` maps commands → checks, run by `_preflight()` before any work.
- **Release + hub** (v1.I): `release` chains make targets + listing + `lint --release` + zip,
  copies the zip, store PNGs and listing.md into `<workspace>/releases/<slug>-<version>/` (the
  upload folder; `/releases/` gitignored — `listing.collect_release`),
  warns at the slot cap (`registry.slots` — used = store PUBLISHED, limit default 2), appends the
  HUMAN publish line, then `hub`. `hub.py` mirrors lamill.io's zod `extensionSchema` as pydantic
  `HubEntry`; entries need a real tool page (`landing_page_url`), else skipped; `store_url`
  null until a `store_id` exists (D-032); status `published` once the store says so, else
  `unlisted` — pages live + noindex, hidden from the hub index (D-035); zero entries → file untouched; writes only
  `<hub_repo>/src/content/extensions.json` and `privacy.json`, never commits. Lint `hub-urls`:
  listing has the privacy + support URLs; `--release` probes both for HTTP 200 and the privacy
  page for "Policy version N".
- **Shared privacy policy** (v1.G, D-036): `privacy-policy.yaml` (version, updated, permission →
  reason) is the one policy for every extension; `privacy.py` loads it (pydantic `Policy`, mirror
  of lamill.io `privacySchema`) and `hub` always writes it to `<hub_repo>/src/content/privacy.json`
  first — even with zero entries — so `lamill.io/extensions/privacy` is live before any tool page.
  Lint `privacy-coverage` (warn dev / error release): recipe permissions ⊆ policy, no host
  permissions, analytics, remote code, or `data_collected`.
- **maps-overlay template** (v1.J, D-031): background `action.onClicked` → inject
  `content-scripts/overlay.js` (shadow-root panel + `renderShell`, toggles); `tabmill:open-page`
  message → `tabs.create` for extension pages; `overlay-preview.html` renders the panel for
  store screenshots + smoke; `TEMPLATE_PERMISSIONS["maps-overlay"] = scripting`.
- **Landing** (v1.K, D-033): `landing.py` — URL = portfolio_site + `landing_path`
  (default first keyword), self-contained brief → `.output/store/landing-brief.md`; `--check`
  probes 200, rewrites only the recipe's `landing_page_url` line, runs lamill's
  `settings gsc submit-sitemap` (soft-fail).
- **Lifecycle CLI** (v1.L, D-034/D-038): the five verbs compose the single steps, which stay
  callable under `advanced`. `new` = starter recipe when none exists, else register +
  generate. `check` = typecheck + unit + smoke + dev lint, every registered extension when no
  slug (keeps going, summary). `ship` = tool-page step (recorded → ✓; live → set
  `landing_page_url` + sitemap; else ↷) → release steps → brief → release lint → zip →
  upload folder → hub; `--publish` checks for a TTY before any work, then uploads; no
  `store_id` → prints the dashboard steps. `status` = catalog rows + registry store state +
  `lifecycle.next_step` (one next command each); `--refresh` = fetchStatus.
- **Catalog** (`cli/tabmill/catalog.py`, v1.D): `list` rows = `recipes/*/` ∪ workspace
  registry — status `recipe` / `generated` / `built` (`.output/chrome-mv3/manifest.json`) /
  `orphan` (registered, no recipe) / `invalid` (YAML error); placeholders = any `‹FILL›` value
  (dotted path) + placeholder URLs (D-015). `create` renders `templates/recipe/extension.yaml.tmpl`;
  `new`/`build` refuse `‹FILL›` in name / summary / single_purpose. Workspace optional for both.
- **Generator** (`cli/tabmill/generate.py`, ADR-0008): for each slug in `registry.json`,
  managed files under `extensions/<slug>/` = `templates/extension/<template>/**` (`*.tmpl`
  rendered) + `recipes/<slug>/**` overlay (same path wins; `extension.yaml` excluded) +
  generated `manifest.gen.json`, `package.json` (base dev toolchain + YAML `dependencies`),
  `src/generated/config.ts` (name, single purpose, privacy line, UTM CTA + footer URLs),
  `README.md`. `tabmill bootstrap` registers the slug; `build` = validate + sync + `make in-docker-build`.
- **popup template**: WXT `srcDir: src`, `wxt.config.ts` passes `manifest.gen.json`; popup shell
  (`src/lib/brand.ts`) renders title, `src/feature/` mount (stub unless the recipe supplies it),
  privacy line, CTA, "Built by Lamill" mark + footer; typed `createMessenger` helper; Vitest
  config test; Playwright smoke (`channel: 'chromium'`, extension ID read from chrome://extensions
  because popup-only extensions have no service worker).
- **Docker bridge**: workspace `make in-docker-<target>` starts the builder container `tabmill-ext`
  (react image, common-parent mount, port 3000) and runs `make <target>` inside, then chowns
  what it created back to the host user (the container runs as root). Node targets refuse on the host.
- **Lint modes**: each policy rule has a dev severity and a release severity; `lint --release`
  (zip for release, release skill, tag CI) applies the release one. `cta-placeholder` = warn → error (D-015).
- **Release**: build → lint --release → smoke → zip → assets → listing → `HUMAN: publish` line. Publish
  (attended) = CWS API v2 upload + publish on an existing item.

- **AI runner** (`ai.py`, D-040): `claude -p <prompt> --output-format json --allowedTools ""
  --max-budget-usd 0.50` (+ `--model` from `tabmill.config.json` `ai_model`). Prompt =
  `prompts/<purpose>_v<N>.md` (front matter `purpose, version, output_schema`; `{{var}}` body;
  `{{schema}}` = the pydantic model's JSON Schema). Reply → one JSON object → pydantic; one
  repair call with the errors; second failure → ✗ with both replies in
  `ideas/<id>/raw/<purpose>-<ts>.txt`. Call record: purpose, prompt_version, model, start/end,
  cost_usd (from the envelope; null = unknown), input_hash, repaired. `TABMILL_AI=replay:<dir>`
  serves `<purpose>_v<N>-<input_hash>.json` (`{model, replies[]}`, first + repair);
  `record:<dir>` writes them. Every command that runs AI ends with `AI: N call(s) · $X · model`
  (`ai.LEDGER`, failed runs included; unknown cost shown as unknown). Tests replay only; `tests/fixtures/ai/` holds a recorded live run.
- **Stage engine** (`idea/engine.py`): fixed order clarify → shape → evidence → check →
  verdict → write; each registered stage writes `ideas/<id>/stages/NN-<stage>.json`
  {stage, kind, input_hash, created, stale, calls[], output}. Resume (`new --resume <id>`) runs
  every stage that is missing, stale, or whose input hash changed (session text + stage inputs
  + upstream hashes) and replays the rest; `new <stage> [id]` forces one and marks later
  stages stale. Session: `ideas/<id>/session.json` {id `YYYYMMDD-<4 words>`, text verbatim,
  input_kind, non_interactive, template hint}.
- **clarify_v1** (`idea/stages/clarify.py`): AI fills `known` (target_user, core_action,
  trigger, pages, done_looks_like) and asks ≤ 5 questions about the empty ones; code drops
  questions about known fields and repeats, stops after 2 rounds (≤ 2 calls). Answers →
  `user` facts verbatim; skipped / `--non-interactive` → `open`, carried as assumptions.
  For a brief (gap-only): its Answers pre-fill `known` and win over the AI's reading; its Open
  questions (verbatim) and any section that failed to parse are asked by code; all five fields
  filled → no AI call. Same `clarify_v1` prompt.
- **Rules engine** (`rules.py` + `rules/lamill.yaml`, D-040): data (permission allowlist, broad
  hosts, name/summary limits, store-name brand denylist) and a severity per context
  (`idea | dev | release`, `skip` = not checked there); predicates in code, keyed by rule id —
  `rules.load` fails if the two drift. Recipe-level rules (perm-broad-host, fill-placeholder,
  cta-placeholder, portfolio-similarity, privacy-coverage, plus v2.D's perm-justification,
  perm-not-allowlisted, store-name-brand, name/summary length, single-purpose,
  template-implemented, slot-free) run through `rules.evaluate()` from both the idea `check`
  stage and `lint.py`; schema, bundle and live-URL rules stay in `lint.py`. Rules that
  `extension.validate` already enforces in dev/release are `skip` there.
- **shape_v1** (`idea/stages/shape.py`): AI proposes single purpose, template or `none-fits` +
  reason, permissions with justifications, trigger, restricted pages, slug candidates, store
  name, summary, keywords, site, CTA, assumptions (brief Proposal passed as a suggestion).
  Code: first valid unused slug (else one from the store name), operator `--template` wins,
  the template's own permissions are added; result = recipe-shaped `draft`.
- **check stage** (`idea/stages/check.py`, kind rule, no AI): `rules.evaluate(draft, "idea")` +
  slots. Its input hash includes the rules, the recipe list and the slot view, so resume re-runs
  it when any of those change. `new <stage> <id>` re-runs one stage and prints the stale ones
  with the `--resume` hint (no auto-continue: later stages may cost AI calls).
- **Evidence** (`idea/evidence.py` providers, `idea/stages/evidence.py`, kind data): providers
  share `collect(keywords, ctx) → status + facts`. lamill: `lamill new validate <primary kw>
  --json` (SERP top-10 domains, AI Overview, People also ask → `real` when its source is
  SerpAPI, else `synthesis` "NOT REAL SERP DATA"; its gate-1 volume is an LLM estimate →
  `synthesis`; its reported cost joins the AI cost line unless served from cache) and
  `lamill new trends <kw> --json` for the first 3 keywords (relative 0–100 interest, not
  volume → `real`). files: `ideas/<id>/evidence/*.md` (front matter `idea, collected` + the
  brief's Demand / Store competition tables; rows without a date take `collected`). brief: its
  Evidence rows. overlap: similarity to existing recipes (`real`, tabmill-computed). treg and
  store competition: declared, `not available`. A failing provider soft-fails. Every keyword
  without real/sourced demand and absent store competition become `missing` facts. Input hash
  = keywords (via shape) + evidence-file hashes, so `evidence add` makes resume re-run it.
  Tests never run lamill or live `claude -p` (conftest guards both).
- **verdict_v1** (`idea/stages/verdict.py`): AI scores reach / outrate / audience / risk /
  effort 0–10 with reasons, risks, needs_evidence. Code (`decide`): weighted score (weights and
  GO / GO-IF thresholds in `rules/lamill.yaml` § verdict — starting values, tuned in v2.H),
  band, NO-GO on any check error, cap at GO-IF when no demand fact or no competition fact is
  real/external (`capped_by`).
- **write** (`idea/stages/write.py`, kind gen): `recipes/<slug>/extension.yaml` (schema v2,
  JSON-quoted values, `idea_id`, provenance = clarify + evidence facts; `‹FILL›` + `# why` only
  for cta_url, store_category and a none-fits template) + `recipes/<slug>/idea.md`. Refuses a
  recipe another idea wrote or an approved one. The CLI prints the portfolio.yaml item
  (`approval: proposed`) as a diff and writes it with `new --apply`.
- **approve** (`idea/approve.py`, human gate 1, terminal only): write + verdict fresh; recipe
  valid; no rule errors (`idea` context, on the file as edited); NO-GO needs `--override
  "<reason>"`; a free slot unless the slug already holds one. Writes the item: approved |
  override, idea_id, recipe_revision, `frozen_sha256` (sha256 of the parsed recipe minus
  `portfolio.UNFROZEN`: version, changelog, landing_page_url, recipe_revision, cta_url,
  store_category), approved_at, slot reserved. Re-approval needs a bumped revision.
  `_recipe()` (every build command) refuses an idea recipe that isn't approved, and a frozen
  one whose fields or revision drifted (`portfolio.drift`). `status` shows such recipes at
  stage `verdict` with `tabmill approve <id>`.
- **ideas** (`engine.summary`): `ideas [list]`, `ideas show <id>` (idea.md, else stage
  summaries), `ideas compare <id> <id>…` (verdict, score, rubric, evidence mix, errors).
- **Tabmill brief v1** (`brief.py`, `schemas/brief_v1.schema.json`): front matter
  (`tabmill_brief: 1`, idea, author, created) + `## Idea · Answers · Proposal · Evidence
  (### Demand, ### Store competition tables) · Risks · Open questions`. Parsed section by
  section, line-based (AI-written values contain `: `, so no YAML load for sections): problems
  are `line N, section … : msg` and the section is dropped, everything else kept. Template
  placeholders (`…`, `<why>`, the trigger option list) count as empty. Facts: evidence row with
  an http(s) source → `external`, without → `synthesis` (↷ downgraded); Answers + Proposal →
  `external_suggestion`. Input: `new --brief <file>`, `new -` (stdin), `new --paste`, bare `new`
  on a terminal; any input is auto-detected as a brief (`---` + `tabmill_brief:`) and saved
  verbatim to `ideas/<id>/brief.md` (id from the brief's `idea`). `brief check <file>` reports
  without starting a session.

## 3. Data shapes / schemas

- **Recipe schema v2** (D-040, `cli/tabmill/schema.py`, `schemas/recipe_v2.schema.json`):
  v1 fields plus `schema_version: 2`, `target: chrome-mv3`, `recipe_revision` (integer; bump
  to change frozen fields after `approve`), `idea_id`, `trigger`, `restricted_pages`,
  `provenance[] {claim, value, source, date, kind}`. A recipe without `schema_version` is v1:
  it still loads; `tabmill doctor --fix` migrates it by inserting the v2 keys as text, so
  comments survive (`recipe_v2.py`).
- **portfolio.yaml** (TOOL_DIR, `portfolio.py`): `slots.limit` (default 2) and `items.<slug>
  {approval: migrated|approved|override, idea_id, recipe_revision, frozen_sha256,
  approved_at, slot: none|reserved}`. Slow-changing tabmill-side record; store state stays
  in registry.json. Free slots = limit − PUBLISHED − reserved.
- **Lifecycle** (`lifecycle.stage`): idea → shaped → evidenced → verdict → approved →
  bootstrapped → checked (registry `checked_version` = recipe version, set by `check`) →
  shipped (release folder or store_id) → published → maintained (an API publish after the
  manual first one).
- **extension.yaml** (original v1.A field list; superseded by the schema above): `name`, `slug`,
  `version`, `single_purpose`, `template`, `permissions[] {name, justification}`,
  `optional_permissions[]`, `portfolio_site`, `landing_page_url`, `target_keywords[]`,
  `cta_text`, `cta_url`, `utm_campaign`, `store_category`, `analytics` (default `false`),
  `theme` (optional). Policy spike suggests adding: `remote_code`, `privacy_policy_url`,
  `data_usage {categories, limited_use}` — decide in v1.E.
- **registry.json**: per slug — `version`, `store_id` (from dashboard "Add new item"),
  `status`, `review_state`, `metrics[] {date, report, value}` (from CSV import).
- **tabmill.config.json** (TOOL_DIR): `builder`, `tool_repo`, optional `workspace` fallback,
  optional `ai_model` (idea-stage `claude -p --model`; empty = Claude Code's default).
  Env `TABMILL_WORKSPACE` / `TABMILL_BUILDER` win; relative paths resolve against TOOL_DIR.

`new clarify [id]` (idea stage; `new <slug>` = deprecated alias for `bootstrap` until v3.A) · `bootstrap` · `try` · `check [slug]` · `ship` (never uploads) ·
`publish` (attended upload) · `status [slug]` · `slots` · `templates` · `doctor [--fix]`.
`settings`: `init`, `skills sync`, `preflight`, `apikeys`. `advanced` (the single steps):
`create build dev test lint zip assets listing landing release hub list`. Output uses `✓ ↷ ✗`.

## 6. Integrations / external APIs

- **Chrome Web Store API v2** — `chromewebstore.googleapis.com`; service account (preferred)
  or OAuth refresh token; scope `.../auth/chromewebstore`. Cannot create items or change
  visibility. Details: `skills/tabmill-release/reference.md`.
- **lamill CLI** — `lamill settings gsc submit-sitemap --site <d>`; landing pages deploy by
  git push to the site repo. No IndexNow (D-016).
- **GitHub** — tabmill is private; workspace CI checks it out with `TABMILL_PAT` (ADR-0007).
- **Metrics** — dashboard CSV export only.

- **Claude Code CLI** — `claude -p`, no tools, budget-capped per call (`ai.py`). Model and
  cost come from its JSON envelope (`modelUsage`, `total_cost_usd`).

## 7. Stack baselines

- **CLI:** Python ≥ 3.11, uv; typer, rich, httpx, pydantic, pyyaml.
- **Extensions (docker only):** Node ≥ 22, pnpm (only), TypeScript ~5.9 strict, WXT 0.21.x
  (ADR-0004), Playwright with `channel: 'chromium'`.

## 9. Risks

- Portfolio/duplicate-functionality policy — the largest store risk (NOTES § Spike 5).
- Cross-root pnpm workspace is undocumented behaviour (D-006).
- WXT is pre-1.0 — pin minor.
- Make variable leakage: the tool Makefile exports container settings; generated Makefiles use `:=`
  so inherited values can't redirect the container (a v1.B bug: build ran in `tabmill-tool`).
- Builder fit: handled by workspace `Makefile.local` (ADR-0005) — can drift from builder changes; Playwright image (v1.46.0) bump needs a Tabmill-owned Dockerfile.
- New-publisher cap of two published extensions.

## 10. Tracked refactors

- **Build-stage logic lives in `cli.py`** (2026-10-15, D-040). `_release`, `_publish`,
  `_tool_page`, `_hub`, `_refresh` hold business logic inside the typer module (~1,000 lines).
  v2's rule is a thin CLI; new idea-stage code follows it, but these helpers stay put in v2 to
  keep the working ship path safe. Move them to a `build` module when one of them next needs a
  real change.
